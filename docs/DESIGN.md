# v2设计边界

任务只通过query及4个工具暴露环境。工单ID为opaque hash，场景标签仅评测元数据可见。VIP与SLA通过反例解耦，政策例外、幂等写入、读写故障和缺失字段具有不同执行要求；验证/测试预先包含部分未见组合。共享机制的合成任务仍不能证明生产泛化。

OpenJudge评分器检查最终状态与证据依赖，以及中间错误写入、重复写入、有效澄清。状态成功和轨迹评价的共同合同避免无读空clarify的假成功。合法的独立只读查询可以并发，不要求固定唯一总顺序。

Budget先落盘预占HTTP尝试，再发请求；中断不会重置次数。actor和optimizer共用账本。Token预留按输入UTF8字节数和输出上限估计，供应商Token与账单另计；未返回用量的失败请求不编造为0费用。

ProviderFailure传播到阶段级并写入脱敏暂停状态；模型格式/输出截断/轮数失败保留为可优化样例。失败模型episode被缓存，避免不停重试挑最好结果。

先pilot判定收益空间，再搜索和冻结，最后单独finalize。候选文件在验证前持久化，预算中断后不必重新付费生成同轮候选。验证答案不进入优化器，测试只在freeze之后读取；冻结Prompt绑定实验配置hash。

最终报告对比baseline/manual/optimized，按任务做配对bootstrap，同时报告改善及退步任务。预实验和小样本bootstrap仅提供探索性证据，不包装为显著提升。
