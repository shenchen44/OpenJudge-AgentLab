# v2预注册实验口径

目标：评估开发集失败轨迹驱动的Prompt候选，在相同模型、非思考模式和任务预算下，是否提高任务成功率，或在成功率不降的前提下降低调用成本。

1. 固定72条受控合成任务及manifest，分pilot12、dev24、validation12、test24。禁止把同一题的简单数字替换当成大量独立机制。声明共享机制的限制，不声称生产泛化。
2. 原始及人工Prompt在看真实模型输出之前冻结。数据政策充分可获取，不隐藏业务规则来造失败。
3. pilot只用于接口、难度和收益空间诊断，不看最终测试。人工方案有收益不保证自动方案可达到同等收益。
4. 优化器仅接收dev失败、客观标准及效率样例。validation仅用于候选选择；不把其轨迹和答案反馈给优化器。默认只一轮一个候选。
5. 选择标准：成功率优先；相同成功率时轨迹不退步、tokens至少降5%。如无合法候选或无收益，保留原始Prompt。demo仅比较脚本工具次数，不作真实效果结论。
6. optimize只输出冻结文件，不加载test。finalize是显式独立阶段，要求同模型、数据、重复次数及任务预算。
7. 主指标为任务合同成功：正确最终状态+必要查询+有效澄清+无错误/多余提交。部分依赖允许不同合法顺序，不强制逐字匹配唯一轨迹。
8. 辅助指标：按机制成功率、工具次数、无效调用、重复写入、tokens、耗时、模型格式/截断失败。接口异常单独暂停，不能作为可优化业务失败。
9. 任务级配对bootstrap及改善/退步任务数保留负面结果；小样本区间只作探索性描述。重复试验按任务分组，不伪造样本量。单次12题/24题不能支持精确的小幅收益结论。
10. 每个HTTP尝试前预占共享持久化次数预算；不自动扩容，重试也计数。Token预留是估计，不保证金额。失败请求未知消耗如实标记。
11. calibrate的24项人工构造fixture是工程回归，不声称独立人工标注。真实人工复核需独立审阅轨迹和标签，不能将fixture改名冒充。
12. 最终结果可以是无提升或成本收益，不换模型、筛题、只报最好一次来保证正向结果。若更改方案，准备新验收集或明确披露测试复用。

## v3执行层补充

同一实验的pilot/search/finalize必须保持concurrency及task-timeout一致。默认并发1。请求用量按任务/Attempt累计所有已记录尝试，unknown用量不能算0成本。Worker中断后重用检查点与剩余步数，completed负面结果缓存不重跑挑优。并发吞吐必须排除缓存重播，并说明是合成环境/模拟传输还是真实API；不把离线故障测试换算成真实模型提升。
